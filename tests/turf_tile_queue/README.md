# Pending turf tile queue

The dedicated fixture compiles a minimal temporary DM world, starts the actual production map manager and uses real Robust grid and transform systems. It repeats 20,000 turf appearance writes three times, checks the area appearance route on 512 cells over two levels, unique-coordinate and no-update controls, final tiles, and an anchored entity through a nonempty/empty/nonempty batch compared with an uncoalesced reference grid. Empty-to-nonempty-to-empty barriers, successful callback writes, nested flush guards and restoration after injected apply failure are checked too.

Nonempty intermediate appearance entries are coalesced in place. Empty entries and a nonempty entry before each empty are retained so Robust still deparents/unanchors on an intermediate empty even if the final tile is nonempty. Current server transform consumers react only to empties; the client sprite consumer invalidates tile visibility for the batch. This deliberately reduces intermediate nonempty TileChangedEvent entries. New consumers requiring their individual history must revisit this contract.

Successful drain detaches both containers and releases their high-water storage. Callback writes remain for the next drain. A failed apply restores the detached batch before callback writes; as historically, a partly applied grid is retried. This differs from historical Clear-after-callback behavior, which discarded callback writes.

CI runs positive, exact historical map manager at `31b11b063e4b10be15472de8a566d9a466781e4c`, and unsafe all-writes dedup modes. Original TRX/log observations must distinguish queue boundedness and retained capacity from empty-transition behavior. Each mode separately runs unchanged NoRuntimes. Robust submodule commit, clean tracked state, selected Git blobs and on-disk original bytes are checked before and after execution. Those grid/transform originals are included with the prepared-source artifact. Source and four DLL/PDB files, SDK/build/test logs, exact-head receipts and original log archive are uploaded. Pure tests only validate source/control/classifier contracts; they do not execute C# or the game.

This is queue count/capacity and grid behavior evidence. It does not measure full Gaia startup RSS, server CPU, production memory, or multiweek OOM behavior. Empty transitions intentionally remain proportional to submitted transitions; the bound applies to repeated nonempty writes between empties.
